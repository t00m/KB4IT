# KB4IT 0.7.10

Pages with broken frontmatter no longer disappear without a word, AppHelp sites classify every page by type of document, and themes now say which KB4IT they need.

- A page whose frontmatter cannot be read (for example an unquoted value containing `: `) is reported with its line and column and counted as `invalid` in the build summary. Set `"fail_on_invalid": true` in `repo.json` to make it fail the build; AppHelp in strict mode always fails.
- `kb4it verify` exits with an error when it finds a problem, so it can gate CI.
- AppHelp: every page needs a `DocType` (`Tutorial`, `How-to guide`, `Reference` or `Explanation`), like techdoc. A page without a valid one is left out of the site. The landing page groups pages by type of document, and search can filter by it.
- A theme that needs a newer KB4IT than the one installed is refused with a clear message, instead of failing somewhere in the build.
- `kb4it create bookshelf` now produces a repository that builds.

**Upgrading an AppHelp site:** the `Kind` key is gone. Give each page a `DocType`, and use the new optional `Layout` key (`faq`, `tips`, `troubleshooting`) for pages that had one of those kinds. Label overrides named `kind_*` or `facet_Kind` are now `doctype_*` and `facet_DocType`. `kb4it verify` lists every page that still needs changing.
